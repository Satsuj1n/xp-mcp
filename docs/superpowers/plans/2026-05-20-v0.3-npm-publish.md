# v0.3 — npm publish + Smithery + awesome-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.3.0 of `xp-mcp` as the npm package `xp-investimentos-mcp`, with a Smithery listing and an awesome-mcp-servers PR — collapsing adoption from a 10-minute `git clone + build` flow to a 30-second `npx` config snippet.

**Architecture:** Three semi-independent sub-components share the tag. Component 1 (npm) is fully internal and gates the others. Component 2 (Smithery) and Component 3 (awesome-mcp PR) are external submissions — non-blocking for the release tag. The first publish of v0.3.0 is **manual without `--provenance`** (OIDC unavailable locally); v0.3.1+ goes through a tag-triggered GitHub Actions workflow with full provenance attestation.

**Tech Stack:** npm registry, GitHub Actions (`actions/checkout@v4`, `actions/setup-node@v4`, `softprops/action-gh-release@v2`), Smithery.ai, Node.js 22 LTS, existing TypeScript build pipeline (`tsc`), existing MCP SDK 1.0.4 stdio server.

**Spec:** `docs/superpowers/specs/2026-05-20-v0.3-npm-publish-design.md`

---

## Phases overview

Tasks 1–7 are **reversible** (branch work, local validation, PR review). Tasks 8–15 cross irreversibility lines (`npm publish` is permanent; tags are mostly permanent; external PRs are public). Pause and confirm before Task 8.

| Phase | Tasks | Side-effects | Reversible? |
|---|---|---|---|
| 1. Code (in branch) | 1–6 | Local + remote branch only | Yes |
| 2. Merge | 7 | Main moves forward | Reverts possible |
| 3. **Bootstrap publish** | 8–9 | **Registry locked at v0.3.0** | **No** |
| 4. Post-publish wiring | 10–12 | Local config + GH Secrets + tag | Yes (token rotation, tag delete) |
| 5. External listings | 13–14 | Public PRs on third-party repos | Yes (close PRs) |
| 6. Workflow validation | 15 | v0.3.1 published via CI with provenance | No (versioned) |

**Files:**

- [ ] **Step 2: Create `release.yml`**

  Write the file with the exact contents below:

  ```yaml
  name: Release

  on:
    push:
      tags:
        - 'v*'

  permissions:
    contents: write
    id-token: write

  jobs:
    publish:
      runs-on: ubuntu-latest
      timeout-minutes: 10
      steps:
        - uses: actions/checkout@v4

        - uses: actions/setup-node@v4
          with:
            node-version: 22
            registry-url: 'https://registry.npmjs.org'
            cache: npm

        - name: Install dependencies
          run: npm ci

        - name: Typecheck
          run: npm run typecheck

        - name: Build
          run: npm run build

        - name: Smoke test MCP server
          run: |
            OUTPUT=$(node dist/index.js <<'EOF'
            {"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"release-ci","version":"0.0.0"}}}
            {"jsonrpc":"2.0","method":"notifications/initialized"}
            {"jsonrpc":"2.0","id":2,"method":"tools/list"}
            EOF
            )
            echo "$OUTPUT" | grep -q '"name":"get_positions"' || { echo "Smoke test failed: get_positions not in tools/list"; exit 1; }
            echo "$OUTPUT" | grep -q '"name":"calculate_allocation_drift"' || { echo "Smoke test failed: calculate_allocation_drift not in tools/list"; exit 1; }

        - name: Publish to npm
          run: npm publish --provenance --access public
          env:
            NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}

        - name: Create GitHub Release
          uses: softprops/action-gh-release@v2
          with:
            generate_release_notes: true
  ```
