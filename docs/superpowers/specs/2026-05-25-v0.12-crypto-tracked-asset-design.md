## 1. Why

Open TODO (2026-05-24, "Cripto Scope B"): make crypto a first-class tracked
`asset_class`, deferred from v0.10 because the **import path was undefined**
("CSV de exchange? entrada manual?"). User decision (2026-05-25): **manual entry
via a new tool** — the simplest path that needs no external file and unblocks the
rest.

v0.10 shipped quote-only (Scope A). v0.11 added multi-source quotes. This wires
crypto holdings into the tracked portfolio (summary / drift) using that quote
infrastructure for valuation.

## 2. Scope

- **In:** add `"CRIPTO"` to `ASSET_CLASSES`.
- **In:** `set_crypto_position(ticker, quantity)` MCP tool — manual entry. Fetches
  the current quote (multi-source, v0.11), computes a **snapshot** market value,
  upserts a `positions` row with `asset_class='CRIPTO'`.
- **In:** `quantity: 0` removes the holding (idempotent single tool, KISS).
- **In:** crypto flows into `get_portfolio_summary` and `calculate_allocation_drift`
  automatically (they aggregate by `asset_class`).
- **In:** README + version bump 0.11.0 → 0.12.0 + CI smoke 15 → 16 tools.

- **Out:** CSV-of-exchange import (a separate, file-dependent path — deferred).
- **Out:** cost basis / P&L for crypto. Manual entry MVP records quantity +
  current market value only (`avg_price_cents`/`invested_cents` stay null). No
  acquisition price is collected, so no profit/loss is shown — only market value.
- **Out:** crypto screening in `suggest_buys`. CRIPTO is non-screenable (no FII/
  ACAO/ETF-style universe), so it lands in `skipped_classes` via the existing
  mechanism. No screening preset is added.
- **Out:** dynamic (read-time) valuation. See §4.

## 3. The tool

```ts
const setCryptoPositionSchema = z.object({
  ticker: z.string().regex(/^[A-Z0-9]{2,10}$/)
    .describe("Crypto symbol, uppercase (e.g. 'BTC')."),
  quantity: z.number().nonnegative()
    .describe("Amount held (fractional ok). 0 removes the holding."),
});
```

Behaviour:

1. `requireOutboundEnabled()` (it fetches a quote — HTTP egress).
2. If `quantity === 0` → delete the `('CRIPTO', ticker)` row, return `{ removed: true }`.
3. Else fetch the quote via `MultiSourceCryptoQuoteSource([MB, Foxbit, Binance])`.
   - On `TickerNotFoundError` → return a per-tool error (don't write a position).
4. Compute `current_price_cents = round(price_brl * 100)` and
   `market_value_cents = round(quantity * price_brl * 100)`.
5. Upsert `positions` row: `asset_class='CRIPTO'`, `external_id=ticker`,
   `name=ticker`, `quantity`, `current_price_cents`, `market_value_cents`;
   `avg_price_cents`/`invested_cents`/`issuer`/… = null; `last_import_id` = null.
6. Return the stored position + `source` (which exchange answered) + DISCLAIMER.

## 4. Valuation: snapshot, not dynamic (key decision)

`get_portfolio_summary` and `calculate_allocation_drift` are **synchronous** and
read the stored `market_value_cents`. Crypto value is set as a **snapshot at
`set_crypto_position` time** (quantity × current price), so those services need
**no change** and stay sync.

- Trade-off: a crypto holding's value in the summary is as of the last
  `set_crypto_position` call, not live. Re-running the tool refreshes it.
- Alternative rejected: read-time valuation (summary/drift fetch live quotes).
  More "correct" but turns two sync services async + network-bound + outbound-
  gated — a large change, out of scope for the MVP. Mirrors how XP positions are
  also snapshots (from the last import).

## 6. Integration (no service code change — verified by tests)

- **summary**: a CRIPTO row aggregates into its own class line; `pct` reflects its
  share of the portfolio market value.
- **drift**: CRIPTO appears in `byClassCents`; if the target_allocation has no
  CRIPTO key, drift shows it as over-target vs 0% (correct — user hasn't set a
  crypto target). The `allClasses` union already handles classes absent from the
  target.
- **suggest_buys**: CRIPTO is not a `ScreenableClass` → if underweight it lands in
  `skipped_classes` (existing path). Add a test asserting it does not throw.

## 7. Edge cases

| Scenario | Behaviour |
|---|---|
| `quantity: 0` for an existing holding | row deleted, `{ removed: true }` |
| `quantity: 0` for a non-existent holding | no-op, `{ removed: true }` (idempotent) |
| ticker not on any source | per-tool error, no position written |
| outbound disabled | `OutboundDisabledError` (whole tool) |
| re-set an existing ticker | upsert: quantity + snapshot value refreshed |
| fractional quantity (0.5 BTC) | fine (`quantity` is REAL) |

## 8. Tests (TDD)

### 8.1 `positions-repo.test.ts` additions (~3)

- `upsertCryptoPosition` inserts a CRIPTO row; re-upsert updates quantity/value.
- `deleteCryptoPosition` removes the row; delete of a missing row is a no-op.

### 8.2 `set-crypto-position.test.ts` (NEW, ~6)

- Happy path: stub `deps.source`, assert stored row (quantity, market_value_cents
  = round(qty*price*100), current_price_cents), source echoed, DISCLAIMER.
- `quantity: 0` deletes; returns `{ removed: true }`.
- Ticker not found → per-tool error, no row written.
- Outbound disabled → `OutboundDisabledError`.
- Fractional quantity computes value correctly.

### 8.3 integration (~3)

- summary with a CRIPTO position → CRIPTO line present with correct value/pct.
- drift with a CRIPTO position and no crypto target → CRIPTO over-target row.
- suggest_buys does not throw with a CRIPTO position present.
