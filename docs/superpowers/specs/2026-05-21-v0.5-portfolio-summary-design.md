## 1. Problem statement

`portfolio-mcp` ships through v0.4 with eight MCP tools, but none gives the LLM a **single-call panorama** of the portfolio. Today the LLM must:

- Call `get_positions` (returns the full list — verbose, ~12 rows per position)
- Aggregate per-class totals client-side (the LLM does the arithmetic, which it sometimes gets wrong)
- Call `calculate_allocation_drift` only if the user has `~/.xp-mcp/allocation.json` configured (most don't yet)
- Manually inspect each `import_xperformance_pdf` response to know the declared `patrimonio_total_brl`

There is no tool that answers *"give me a 1-screen overview of my portfolio: classes, top positions, P&L, FGC coverage, maturity profile, and whether my last import matched the broker's declared total."*

`get_portfolio_summary` fills that gap. It is the **inspection-tier analog** of `calculate_allocation_drift`: zero outbound calls, zero config required, immediately useful after the first import.

The reconciliation half is equally important: today there is no way for a user to know whether their import is **complete**. The XPerformance PDF declares a `patrimônio total` in its header; the parser may have failed to classify some rows, dropping them silently. Without comparing declared vs computed, the user trusts the LLM blindly. The reconciliation gap is the audit trail.

## 2. Goals

- Ship 1 new MCP tool: `get_portfolio_summary` (no input parameters — global panorama)
- Migrate schema v1 → v2 to persist `declared_total_cents` and `reference_date` as dedicated columns on the `imports` table (currently serialized inside the `notes` blob)
- Backfill the new columns for existing imports by parsing the historical `notes` strings (lossless upgrade)
- Compose the output from 5 independently-testable pure functions
- Maintain the project's clean architecture pattern: `services/portfolio-summary.ts` (pure) + `tools/get-portfolio-summary.ts` (I/O thin wrapper)
- Maintain TDD discipline (RED → GREEN → COMMIT per task)
- Update `ci.yml` + `release.yml` smoke tests to verify 9 tools register
- Bump version `0.4.0` → `0.5.0` (minor: backwards-compatible schema migration + new tool)

## 3. Non-goals

- **`asset_class` filter input** — `get_positions` already does per-class filtering; `get_portfolio_summary` is intentionally global
- **Configurable maturity buckets** — buckets are fixed (short <1y, medium 1-3y, long >3y); user-tunable thresholds defer to a future iteration if requested
- **Configurable top N** — N is fixed at 5
- **Concentration by issuer** (FGC limit awareness across issuers) — interesting but separate concern; defer
- **Weighted average yield / weighted maturity** — defer to v0.6+
- **Reconciliation against historical imports** — only the most recent declared import is compared
- **CSV-side declared total** — XP CSV exports don't carry a declared `patrimonio total`; only XPerformance PDF does
- **Tool-side caching** — pure computation over current DB state; no cache layer (DB read is cheap, freshness matters)

## 4. Architecture

```text
┌──────────────────────────────────────────────┐
│ src/tools/get-portfolio-summary.ts           │
│   zod schema (empty input)                    │
│   handler: reads DB → calls pure function     │
└──────────────────┬───────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────────┐
│ src/services/portfolio-summary.ts            │
│   computePortfolioSummary(positions, lastDecl)│
│                                               │
│   Internal composition (all pure, exported):  │
│   • aggregateByClass(positions)               │
│   • pickTopPositions(positions, n, total)     │
│   • computeReconciliation(computed, lastDecl) │
│   • computeFgcCoverage(positions, total)      │
│   • computeMaturityBuckets(positions, asOf)   │
└──────────────────────────────────────────────┘
        ▲                              ▲
        │                              │
┌───────┴──────────────┐    ┌─────────┴───────────────┐
│ positions-repo.ts    │    │ imports-repo.ts (NEW)   │
│ listPositions(db)    │    │ getLastDeclaredImport(db)│
└──────────────────────┘    └─────────────────────────┘
```

**Why `imports-repo.ts` is new:** `positions-repo.ts` today only writes to the `imports` table (`createImportRecord`, `updateImportCounts`). Reading the latest declared import is a read concern with its own query; isolating it keeps `positions-repo.ts` from drifting into mixed responsibilities and is straightforward to test independently.

**Why `services/portfolio-summary.ts` mirrors `services/drift.ts`:** same pattern, same boundary discipline (pure function over rows, no DB/FS), same `round2` helper at the output boundary.

## 5. Output shape

### TypeScript interface

```ts
export interface PortfolioSummary {
  // Totals (always present)
  total_market_value_brl: number;
  positions_count: number;
  computed_as_of: string;            // ISO timestamp = max(positions.last_imported_at)

  // P&L (subset where invested_cents != null)
  total_invested_brl: number;
  total_unrealized_pl_brl: number;
  total_unrealized_pl_pct: number | null;  // null when total_invested_brl == 0
  pl_coverage: {
    positions_with_pl_count: number;
    positions_total: number;
  };

  // Per-class breakdown (sorted by market_value_brl desc)
  by_class: Array<{
    asset_class: "TESOURO" | "RENDA_FIXA_PRIVADA" | "FII" | "ETF" | "ACAO" | "FUNDO";
    count: number;
    market_value_brl: number;
    pct_of_total: number;            // 0..1
    invested_brl: number | null;     // null if no position in class has invested_cents
    unrealized_pl_brl: number | null;
    unrealized_pl_pct: number | null;
  }>;

  // Top 5 positions by market_value
  top_positions: Array<{
    asset_class: string;
    external_id: string;
    name: string;
    market_value_brl: number;
    pct_of_total: number;
  }>;

  // FGC coverage (relevant mainly for RENDA_FIXA_PRIVADA)
  fgc_coverage: {
    covered_brl: number;             // sum where has_fgc = 1
    not_covered_brl: number;         // sum where has_fgc = 0
    unknown_brl: number;             // sum where has_fgc IS NULL
    covered_pct: number;             // covered_brl / total_market_value_brl
  };

  // Maturity buckets
  maturity_buckets: {
    short_brl: number;               // maturity < 1y from horizon_from
    medium_brl: number;              // 1-3y
    long_brl: number;                // > 3y
    no_maturity_brl: number;         // null maturity_date (ACAO/FII/ETF/FUNDO)
    short_count: number;
    medium_count: number;
    long_count: number;
    no_maturity_count: number;
    horizon_from: string;            // YYYY-MM-DD = computed_as_of[:10]
  };

  // Reconciliation (null when no import has a declared_total_cents)
  reconciliation: {
    declared_total_brl: number;
    computed_total_brl: number;      // = total_market_value_brl (repeated for clarity)
    gap_brl: number;                 // computed − declared (sign preserved)
    gap_pct: number;                 // gap_brl / declared_total_brl
    declared_reference_date: string; // YYYY-MM-DD from the PDF header
    declared_imported_at: string;    // ISO timestamp of the import row
    declared_source_path: string;    // absolute path of the PDF that was imported
    is_stale: boolean;               // true if declared_reference_date < computed_as_of[:10]
  } | null;

  warnings: string[];
}
```

### Design decisions explicit in this shape

1. **`invested_brl: null` per class when no position in the class has `invested_cents`** (typical for TESOURO from PDF). Choosing `null` over `0` avoids the false signal that the position was free.
2. **`gap_brl = computed − declared`** (sign preserved). Negative = lost positions during import (common). Positive = computed more than declared (rare, suggests bug).
3. **`is_stale` is boolean, not a threshold of days.** True iff `declared_reference_date < computed_as_of[:10]`. Warning is added to `warnings[]` when stale.
4. **`horizon_from` in `maturity_buckets`** makes buckets auditable — buckets computed on different dates give different results for the same position (a CDB maturing Nov/2026 is "short" today and "matured" in Dec/2026).
5. **`top_positions` repeats `pct_of_total`** instead of forcing the client to recompute. Small redundancy, fewer errors.
6. **`pl_coverage` exposes the subset** over which `total_unrealized_pl_brl` is computed. PDF-only portfolios will have `positions_with_pl_count = 0`.

## 6. Schema migration (v1 → v2)

### Changes to `imports` table

```sql
ALTER TABLE imports ADD COLUMN declared_total_cents INTEGER;
ALTER TABLE imports ADD COLUMN reference_date TEXT;
```

Both nullable. Old imports without declared remain `NULL`.

### Migration runner

`SCHEMA_VERSION` constant bumps from `1` → `2`.

`applySchema(db)` reads `meta.schema_version`:

- If absent or `1`: run `migrateV1ToV2(db)` before the idempotent DDL loop
- If `2` or higher: no-op

`migrateV1ToV2(db)`:

1. `ALTER TABLE imports ADD COLUMN declared_total_cents INTEGER` — wrapped in try/catch to ignore the "duplicate column" error when migration is re-run on already-migrated DBs
2. Same for `reference_date`
3. **Backfill**: `SELECT id, notes FROM imports WHERE notes IS NOT NULL`. For each row, parse the `notes` string for:
   - `patrimonio_total_cents=(\d+)` → write to `declared_total_cents`
   - `reference_date=(\d{4}-\d{2}-\d{2})` → write to `reference_date`
   - `UPDATE imports SET declared_total_cents = ?, reference_date = ? WHERE id = ?`
4. Update `meta.schema_version = '2'`

The whole migration runs inside a single transaction.

### Changes to writers

`createImportRecord(db, { sourceType, sourcePath, totalRows, declaredTotalCents?, referenceDate? })`:

- Two new optional parameters
- INSERT writes them into the new columns when provided

`import-xperformance-pdf.ts`:

- Passes `declaredTotalCents: parsed.patrimonio_total_cents` and `referenceDate: parsed.reference_date` to `createImportRecord`
- Removes the `patrimonio_total_cents=...` and `reference_date=...` fragments from the `notes` string (they now live in dedicated columns; `notes` keeps only warnings)

`import-extract-csv.ts`: no changes (CSV has no declared total).

### Read path

`getLastDeclaredImport(db)`:

```sql
SELECT id, declared_total_cents, reference_date, source_path, imported_at
FROM imports
WHERE declared_total_cents IS NOT NULL
ORDER BY imported_at DESC
LIMIT 1
```

Returns `null` when no row matches.

## 7. Sub-function contracts

All in `src/services/portfolio-summary.ts`. All pure. All exported (so they can be unit-tested directly).

### `aggregateByClass(positions: PositionRow[]): ByClassRow[]`

- Input: raw `PositionRow[]` (positions with `market_value_cents == null` already filtered out by the caller)
- Output: one row per asset class present in `positions`, sorted by `market_value_brl` desc
- Per-class P&L: aggregated over the subset where `invested_cents != null`. If the subset is empty, `invested_brl`, `unrealized_pl_brl`, `unrealized_pl_pct` are all `null`
- `pct_of_total` is `market_value_cents_class / total_market_value_cents`

### `pickTopPositions(positions: PositionRow[], n: number, totalCents: number): TopPosition[]`

- Returns the top `n` positions by `market_value_cents` desc
- Ties broken by `external_id` asc (deterministic)
- Returns fewer than `n` if `positions.length < n`
- `pct_of_total = position.market_value_cents / totalCents`

### `computeReconciliation(computedCents: number, computedAsOf: string, lastDecl: LastDeclared | null): Reconciliation | null`

- `LastDeclared = { declared_total_cents, reference_date, source_path, imported_at }`
- Returns `null` when `lastDecl == null`
- `gap_cents = computedCents − lastDecl.declared_total_cents`
- `gap_pct = gap_cents / lastDecl.declared_total_cents` (BRL precision is fine; declared_total > 0 by definition)
- `is_stale = lastDecl.reference_date < computedAsOf.slice(0, 10)`

### `computeFgcCoverage(positions: PositionRow[], totalCents: number): FgcCoverage`

- Three buckets: `has_fgc == 1` → covered, `has_fgc == 0` → not_covered, `has_fgc IS NULL` → unknown
- `covered_pct = covered_cents / totalCents`

### `computeMaturityBuckets(positions: PositionRow[], horizonFromDate: string): MaturityBuckets`

- `horizonFromDate` format `YYYY-MM-DD`
- For each position:
  - `maturity_date == null` → `no_maturity` bucket
  - `maturity_date` parse-fails (not `YYYY-MM-DD`) → `no_maturity` bucket + warning emitted by the orchestrator
  - Computes `days = (maturityDate − horizonFromDate) / dayMs`. Negative days (past maturity) → `short` bucket + warning emitted by the orchestrator
  - `days < 365` → `short`
  - `365 <= days < 365*3` → `medium`
  - `days >= 365*3` → `long`

### `computePortfolioSummary(allPositions: PositionRow[], lastDecl: LastDeclared | null): PortfolioSummary`

1. Filter `allPositions` to `positionsWithMv = allPositions.filter(p => p.market_value_cents != null)`
2. If `positionsWithMv.length === 0`: return an empty-state summary (totals=0, `by_class=[]`, `top_positions=[]`, all bucket counts=0, `reconciliation` computed if `lastDecl` exists with `computed_total_brl=0`, plus warnings)
3. Compute `totalCents = sum(market_value_cents)`, `computedAsOf = max(last_imported_at)`
4. Call each sub-function in turn
5. Aggregate warnings:
   - Positions skipped: `"N positions skipped (no market value)"`
   - Stale reconciliation: `"Declared total dates from <date>; computed reflects state as of <date>"`
   - Large gap: `"Reconciliation gap is N% (R$ X); possible import miss"` when `|gap_pct| > 0.01`
   - No declared import: `"No XPerformance PDF imported yet; reconciliation unavailable"` when `lastDecl == null` and `positionsWithMv.length > 0`
   - Past-maturity positions: `"N positions have past maturity (counted as short bucket)"`
   - Malformed maturity dates: `"N positions have malformed maturity_date (counted as no_maturity)"`
6. Convert cents → BRL at the output boundary using `round2`

## 9. Edge cases & warnings

| Cenário | Comportamento |
| --- | --- |
| DB vazio (0 positions) | totals=0, `by_class=[]`, `top_positions=[]`, `reconciliation=null`, `warnings=["No positions in database. Run import_xperformance_pdf or import_extract_csv first."]` |
| DB tem positions, nenhum import com declared | `reconciliation=null`, `warnings=["No XPerformance PDF imported yet; reconciliation unavailable"]` |
| Declared stale | `reconciliation.is_stale=true`, `warnings` inclui a mensagem de stale |
| `abs(gap_pct) > 0.01` | warning de "large reconciliation gap" |
| Todas posições sem `invested_cents` | `total_invested_brl=0`, `total_unrealized_pl_pct=null`, `pl_coverage.positions_with_pl_count=0`, **sem warning** (caso normal de PDF-only) |
| Posições com `market_value_cents = null` | filtradas, contadas em warning |
| `maturity_date` no passado | bucket `short`, warning |
| `maturity_date` malformado | bucket `no_maturity`, warning |
| Migration roda em DB já v2 | colunas já existem, `ADD COLUMN` falha com "duplicate column" → ignorada; backfill é idempotente (re-parsa o mesmo `notes`, escreve os mesmos valores) |
| Migration roda em DB onde nenhum import tem `notes` com `patrimonio_total_cents=` | colunas adicionadas, backfill é no-op |

## 12. Out of scope for this spec

Defer to v0.6+ (não confundir com bugs do v0.5):

- `weighted_avg_yield` ponderado por position size (relevante pra RENDA_FIXA_PRIVADA com `rate` field)
- `weighted_avg_maturity` em anos
- Concentração por issuer (FGC awareness across issuers, R$ 250k limit per CPF per issuer)
- Persistência de snapshots históricos (`get_portfolio_summary_at(date)`)
- Comparação contra um snapshot anterior ("diff since 2026-04-21")
- Sugestões automáticas baseadas no summary (já é trabalho do `suggest_buys` na v0.6+)

## 13. Risk & rollback

- **Schema migration** é o ponto mais sensível. Mitigation: roda em transaction, idempotente, backfill é parse de string (não destrutivo — o `notes` original permanece intacto). Rollback manual seria possível dropando as 2 colunas (mas v2 → v1 nunca foi necessário antes; não automatizar)
- **Backfill** depende do formato exato do `notes` escrito por v1. O `import-xperformance-pdf.ts` v1 produz `patrimonio_total_cents=12345` e `reference_date=2026-05-21` separados por `\n`. Testes cobrem esse formato; outros formatos serão ignorados (deixam coluna null, mesmo comportamento de quem nunca importou PDF)
- **Versão `src/index.ts`** atualmente diz `"0.1.0"` (desatualizado desde v0.2). Atualizar pra `"0.5.0"` aqui pode causar dúvida ("por que não atualizou em v0.3/0.4?"). Documentar no commit. Sem regression de comportamento — o nome do server na MCP capability negotiation usa essa string apenas como display
