## 1. Problem statement

`portfolio-mcp` v0.3 ships three pillars: import (PDF/CSV → SQLite), inspection (`get_positions`), and rebalance math (`calculate_allocation_drift`). All three are **local-first, read-only, offline**.

The user's portfolio is now well-modelled, but the system has no opinion on **what to buy**. `calculate_allocation_drift` answers "how much off-target am I?" but stops at the class level: *"buy R$ 2.247 in some FII"* — it doesn't say *which* FII.

The next valuable step is an **investment advisor** that:

- Reads the user's profile (risk tolerance, horizon, objective, exclusions, free-form notes)
- Fetches real-world market data (quotes + fundamentals) from external sources
- Ranks/screens assets against the profile + drift output
- Produces actionable suggestions (still framed as educational analysis, not registered investment advice)

v0.4 ships the **foundations**: profile management, market data fetching with caching, and asset screening. v0.5 will ship the **orchestrator** (`suggest_buys`) that combines all of these into a single recommendation flow. Splitting prevents the "big bang" anti-pattern — v0.4 alone is useful (user can compose flows via Claude chat).

The spec is also the **first feature that breaks the v0.3 promise of "zero outbound HTTP"** — outbound calls to brapi.dev are required to fetch market data. This is gated as **opt-in** at the profile level: users who only want the v0.3 surface get the same offline guarantee.

## 2. Goals

- Ship 4 MCP tools in v0.4: `set_advisor_profile`, `get_advisor_profile`, `get_market_data`, `screen_assets`
- Persist the advisor profile at `~/.xp-mcp/advisor-profile.json` (hybrid schema: structured fields + free-form `notes`)
- Fetch quotes and fundamentals from **brapi.dev** with anonymous-first auth (opt-in token upgrade)
- Cache market data in **SQLite** (`market_data_cache` table) with TTL differentiated by data type (60min / 24h / 7d)
- Refactor `src/parsers/pdf-xperformance.ts` + `src/parsers/csv-extract.ts` into `src/adapters/xp/` (explicit adapter-pattern preparation for multi-broker)
- Treat all outbound HTTP as **opt-in via `outbound_enabled: true` in profile**, gated at function-call level (not server initialization)
- Include disclaimer ("Análise educacional, não recomendação de investimento") in the output of any tool that ranks/suggests assets
- Maintain TDD discipline (RED → GREEN → REFACTOR) per project convention
- Update `ci.yml` + `release.yml` smoke tests to verify all 4 new tools register

## 3. Non-goals

- **`suggest_buys` orchestrator** — deferred to v0.5; v0.4 exposes the raw building blocks
- **Multi-source adapter** (CVM open data, Tesouro Direto API, exchange APIs for crypto) — only brapi.dev in v0.4; `MarketDataSource` interface designed to support more sources later
- **Watchlist persistence** — no `~/.xp-mcp/watchlist.json` in v0.4
- **Crypto adapter** — listed in roadmap, but not in v0.4 (brapi-only universe excludes crypto)
- **Real-time / streaming quotes** — brapi gives delayed quotes; v0.4 uses cached snapshots
- **Backtesting / forecasting** — pure historical analytics out of scope (no "what would my portfolio return have been?")
- **CVM-registered recommendations** — explicit non-goal; all output is framed as educational analysis
- **Auto-execution of buys** — read-only architecture is preserved; tool never places orders
- **Schema migrations versioning** — v0.4 uses additive `CREATE TABLE IF NOT EXISTS`; versioned migrations introduced when a non-additive change requires it
- **Rename of `~/.xp-mcp/` data directory** — defer to v1.0 (breaking change for existing users)
- **Renaming `import_xperformance_pdf` → `import_xp_xperformance_pdf`** — keep current tool names to avoid breaking the MCP contract; internal code moves to `src/adapters/xp/`

## 4. Decisions log

Resolved during brainstorming. Recorded so the implementation plan and future readers see *why*, not just *what*.

| # | Question | Decision | Rationale |
|---|---|---|---|
| 1 | Scope of "advisor suggestion" — class-level rebalance vs ticker-level within positions vs universe screening | **Universe screening** (option #3 of the brainstorm) | User wants the tool to look beyond current holdings — "top 5 FIIs by DY" is the high-leverage capability. Class-level alone duplicates v0.2's drift; ticker-only-within-positions is too narrow once we already pay the cost of integrating market data. |
| 2 | Market data source | **brapi.dev only** in v0.4; `MarketDataSource` interface abstract from day 1 | brapi.dev covers B3 stocks + FIIs + ETFs + fundamentals + free tier sufficient for personal use. Multi-source (CVM, TD API) deferred — adapter interface makes adding sources non-breaking. |
| 3 | Profile shape | **Hybrid: structured fields + free-form `notes`** (option #4 of the brainstorm) | Structured part (risk_tolerance, horizon, objective, excluded_tickers) drives deterministic scoring; `notes` is a soft constraint applied by the LLM (e.g., "evitar tabaco"). Combines auditability with flexibility. |
| 4 | Architecture — core update vs separate package | **Core update — v0.4 of `portfolio-mcp`** | User chose this. Trade-off accepted: README must clarify "Local-first by default; advisor features (opt-in) make outbound calls". Single package is simpler to maintain at current scale. |
| 5 | Tool granularity | **Decomposed — 4 tools in v0.4 + `suggest_buys` in v0.5** | Matches MCP-native pattern: small tools the LLM composes. Mirrors the existing core (`get_positions` + `import_*` + `calculate_allocation_drift`). Avoids "god object" tool anti-pattern. |
| 6 | Phasing within v0.4 | **A — phased (4 tools in v0.4; `suggest_buys` deferred to v0.5)** | `suggest_buys` is an orchestrator whose design depends on usage patterns of `screen_assets` + profile. Designing it speculatively risks rework. Phasing buys feedback loop. |
| 7 | Package rebrand timing | **Apply rebrand `xp-investimentos-mcp` → `portfolio-mcp` immediately, pre-publish** | v0.3 was never published to npm. Renaming now is free; after publish it requires a deprecation chain. Commit `f05414c` applied the rename. |
| 8 | Opt-in mechanism for outbound HTTP | **Field `outbound_enabled` in `~/.xp-mcp/advisor-profile.json`**, checked at function-call level (not at server init) | Profile is already the source of truth for the user's advisor configuration; storing the gate there keeps it auditable, versionable (dotfiles), and prevents env-var-vs-file split brain. Function-level check prevents LLM bypass. |
| 9 | Disclaimer / compliance posture | **In-band via `warnings` array** on every ranked output; one-time `accepted_disclaimer_at` ISO timestamp persisted in profile | Tool is positioned as educational analysis (no CVM CNPI registration), aligning with how Yahoo Finance, Investidor10, etc operate. Per-call `accept_disclaimer=true` required when first enabling outbound. |
| 10 | brapi auth posture — anonymous-first vs token-first | **Anonymous-first**; user adds optional `brapi_token` to profile if hitting rate limits | Zero-setup default matches the project's "open the box and it works" ethos. Token is an opt-in escape hatch inside the opt-in (advisor enabled + token set). |
| 11 | Cache storage — SQLite vs JSON files vs in-memory | **SQLite — new table `market_data_cache` in the existing `~/.xp-mcp/data.db`** | Reuses the existing DB connection (no new infra). Atomic writes prevent race conditions. TTL queries become trivial via SQL `WHERE cached_at > datetime('now', '-X minutes')`. |
| 12 | Cache TTL defaults | **60 min for quotes, 24 h for fundamentals, 7 d for universe lists** | Quotes change intraday; fundamentals change quarterly; universe (listings) rarely changes. Differentiation matches data freshness reality. User can override per-call via `cache_ttl_minutes` input. |
| 13 | Failure mode for `get_market_data` with multiple tickers | **Partial failure** — per-ticker `error` field; whole call succeeds even if some tickers fail | All-or-nothing would frustrate UX when brapi has spotty data on 1 of 10 tickers. Partial failure mirrors common patterns (graphql `errors` array, OpenAI batch APIs). |
| 14 | Refactor of XP-specific code | **Move `src/parsers/pdf-xperformance.ts` + `src/parsers/csv-extract.ts` → `src/adapters/xp/`** as part of v0.4 | Makes the adapter pattern explicit, matches the rebranded `portfolio-mcp` ambition. ~10 minutes of work prevents permanent architectural confusion. |
| 15 | Test framework for new code | **`node --test` + DI mocks** (no Jest, no Vitest) | Stays consistent with existing v0.1-v0.3 testing setup. Adds no new dev dependencies. |

## 6. Component: `advisor/profile.ts`

### 6.1 Profile schema (zod)

```ts
import { z } from "zod";

export const ADVISOR_PROFILE_SCHEMA_VERSION = 1 as const;

export const assetClassEnum = z.enum([
  "TESOURO",
  "RENDA_FIXA_PRIVADA",
  "FII",
  "ETF",
  "ACAO",
  "FUNDO",
]);

export const advisorProfileSchema = z.object({
  schema_version: z.literal(ADVISOR_PROFILE_SCHEMA_VERSION).default(ADVISOR_PROFILE_SCHEMA_VERSION),

  // Capability gate
  outbound_enabled: z.boolean().default(false),
  accepted_disclaimer_at: z.string().datetime().optional(),

  // Structured part
  risk_tolerance: z.number().int().min(1).max(10),
  horizon_years: z.number().positive(),
  objective: z.enum(["income", "growth", "balanced"]),
  monthly_income_target_brl: z.number().nonnegative().optional(),

  // Exclusions
  excluded_classes: z.array(assetClassEnum).default([]),
  excluded_tickers: z.array(z.string().regex(/^[A-Z0-9]{4,6}$/)).default([]),

  // Free-form
  notes: z.string().default(""),

  // Optional brapi token
  brapi_token: z.string().optional(),
});

export type AdvisorProfile = z.infer<typeof advisorProfileSchema>;
```

### 6.2 Profile repo API

```ts
const PROFILE_PATH = `${process.env.HOME}/.xp-mcp/advisor-profile.json`;

export async function loadProfile(): Promise<AdvisorProfile | null>;
export async function saveProfile(profile: AdvisorProfile): Promise<void>;  // atomic: write to tmp + rename
export async function requireProfile(): Promise<AdvisorProfile>;            // throws ProfileMissingError
export async function requireOutboundEnabled(): Promise<AdvisorProfile>;    // throws ProfileMissingError | OutboundDisabledError | DisclaimerRequiredError
```

**Atomic write semantics**:

1. Write JSON to `${PROFILE_PATH}.tmp.${pid}`
2. `fs.renameSync(tmp, PROFILE_PATH)` (atomic on POSIX)
3. Prevents corruption if process is killed mid-write

**Disclaimer enforcement**:

- `outbound_enabled=true` requires `accepted_disclaimer_at` to be non-null
- `set_advisor_profile` rejects with `DisclaimerRequiredError` if user sets `outbound_enabled=true` without `accept_disclaimer=true` in the tool call

## 7. Component: `advisor/market-data/`

### 7.1 `MarketDataSource` interface

```ts
// src/advisor/market-data/source.ts
export interface Quote {
  ticker: string;
  price_brl: number;
  change_pct: number;
  volume: number;
  market_cap_brl: number | null;
  updated_at: string;  // ISO from source
}

export interface Fundamentals {
  ticker: string;
  dividend_yield_pct: number | null;
  pl_ratio: number | null;
  pvp_ratio: number | null;
  roe_pct: number | null;
  vacancy_pct: number | null;  // FII-specific
  updated_at: string;
}

export interface UniverseListItem {
  ticker: string;
  name: string;
  asset_class: AssetClass;
}

export interface MarketDataSource {
  readonly name: string;  // "brapi.dev"
  getQuote(ticker: string): Promise<Quote>;
  getFundamentals(ticker: string): Promise<Fundamentals>;
  listUniverse(assetClass: "FII" | "ACAO" | "ETF"): Promise<UniverseListItem[]>;
}
```

### 7.2 `BrapiSource` implementation

- Base URL: `https://brapi.dev/api`
- Optional `?token=…` appended if `brapi_token` set in profile
- Endpoints used:
  - `GET /quote/{ticker}` → quote
  - `GET /quote/{ticker}?fundamental=true` → quote + fundamentals
  - `GET /quote/list?type=fund` → FII universe
  - `GET /quote/list?type=stock` → ACAO universe
  - `GET /quote/list?type=etf` → ETF universe
- Parse responses to the canonical `Quote` / `Fundamentals` / `UniverseListItem` shapes; brapi-specific fields are dropped to keep the interface stable

### 7.3 Retry + timeout (`fetch.ts`)

```ts
export async function fetchWithRetry(
  url: string,
  opts: { timeout_ms?: number; max_retries?: number } = {}
): Promise<unknown> {
  const timeout = opts.timeout_ms ?? Number(process.env.BRAPI_TIMEOUT_MS) ?? 5000;
  const maxRetries = opts.max_retries ?? 2;

  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      const res = await fetch(url, { signal: AbortSignal.timeout(timeout) });
      if (res.status === 429) {
        const wait = 1000 * Math.pow(2, attempt);
        await sleep(wait);
        continue;
      }
      if (!res.ok) throw new BrapiError(`HTTP ${res.status} for ${url}`, { status: res.status });
      return await res.json();
    } catch (err) {
      if (attempt === maxRetries) throw err;
      await sleep(500 * (attempt + 1));
    }
  }
}
```

### 7.4 Cache schema (additive migration)

Added to `src/storage/schema.ts`:

```sql
CREATE TABLE IF NOT EXISTS market_data_cache (
  ticker        TEXT NOT NULL,
  data_type     TEXT NOT NULL,                            -- 'quote' | 'fundamentals' | 'universe'
  source        TEXT NOT NULL DEFAULT 'brapi.dev',
  payload_json  TEXT NOT NULL,
  cached_at     TEXT NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (ticker, data_type, source)
);

CREATE INDEX IF NOT EXISTS idx_mdc_cached_at ON market_data_cache(cached_at);
```

Migration policy: `CREATE TABLE IF NOT EXISTS` runs at every DB init. Existing v0.3 DBs gain the table on first v0.4 run.

### 7.5 Cache repo API

```ts
// src/advisor/market-data/cache.ts
export interface CachedEntry<T> {
  data: T;
  cached_at: string;        // ISO
  age_seconds: number;
}

export class MarketDataCache {
  constructor(private db: Database) {}

  get<T>(ticker: string, dataType: 'quote'|'fundamentals'|'universe', maxAgeMinutes: number): CachedEntry<T> | null;
  put(ticker: string, dataType: string, payload: unknown): void;

```

### 7.6 TTL defaults

| Data type | Default TTL | Reason |
|---|---|---|
| `quote` | 60 min | Intraday quote movement; balances staleness vs API cost |
| `fundamentals` | 1440 min (24 h) | Updates only on new quarterly reports |
| `universe` | 10080 min (7 d) | Listings/delistings are rare |

User-overridable per call via `cache_ttl_minutes` input parameter.

## 8. Component: `advisor/screening.ts` (pure)

### 8.1 API

```ts
export interface ScreenCriteria {
  sort_by: 'dividend_yield' | 'pvp' | 'pl' | 'roe' | 'price_change_30d' | 'market_cap';
  order: 'asc' | 'desc';
  filters: {
    min_market_cap_brl?: number;
    max_pvp?: number;
    min_dividend_yield_pct?: number;
    min_roe_pct?: number;
    max_vacancy_pct?: number;
  };
  limit: number;
}

export interface ScreenInput {
  candidates: Array<{ ticker: string; quote: Quote; fundamentals: Fundamentals }>;
  criteria: ScreenCriteria;
  excluded_tickers: string[];
}

export interface ScreenResult {
  ticker: string;
  quote: Quote;
  fundamentals: Fundamentals;
  score: number;     // normalized 0..1 against the sorted population
  why: string;       // human-readable rank reason (e.g., "DY 11.8% (1.4× class median)")
}

export function screen(input: ScreenInput): ScreenResult[];
```

### 8.2 Algorithm

1. Drop candidates whose ticker is in `excluded_tickers`
2. Drop candidates that fail any active filter
3. Compute score: normalized rank by `sort_by` field, considering `order`
   - If candidate's `sort_by` field is null, score is 0 (sorted last)
4. Compute `why` for the top candidates relative to the median of that field in the filtered pool
5. Return `limit` highest-scored candidates

**Determinism**: same `(candidates, criteria, excluded_tickers)` input always yields same output. Enables snapshot testing.

## 10. Error taxonomy (`advisor/errors.ts`)

```ts
export abstract class AdvisorError extends Error {
  abstract readonly code: string;
  readonly recoverable: boolean = false;
}

// User-actionable
export class OutboundDisabledError extends AdvisorError {
  readonly code = "OUTBOUND_DISABLED";
}
export class ProfileMissingError extends AdvisorError {
  readonly code = "PROFILE_MISSING";
}
export class ProfileInvalidError extends AdvisorError {
  readonly code = "PROFILE_INVALID";
  constructor(message: string, public zodErrors: z.ZodIssue[]) { super(message); }
}
export class DisclaimerRequiredError extends AdvisorError {
  readonly code = "DISCLAIMER_REQUIRED";
}

// Transient
export class BrapiRateLimitError extends AdvisorError {
  readonly code = "BRAPI_RATE_LIMIT";
  readonly recoverable = true;
  constructor(message: string, public retryAfterSeconds: number) { super(message); }
}
export class BrapiTimeoutError extends AdvisorError {
  readonly code = "BRAPI_TIMEOUT";
  readonly recoverable = true;
}

// Permanent
export class TickerNotFoundError extends AdvisorError {
  readonly code = "TICKER_NOT_FOUND";
  constructor(public ticker: string) { super(`Ticker not found: ${ticker}`); }
}
```

**MCP tool layer wraps**: every tool's outer handler `try { ... } catch (e) { if (e instanceof AdvisorError) return { ok: false, error: { code: e.code, message: e.message, recoverable: e.recoverable } } else throw e; }`. LLM reads `error.code` to decide.

## 11. Testing strategy

Project convention is TDD (RED → GREEN → REFACTOR), `node --test` runner, no Jest/Vitest.

### 11.1 Per-module test plan

| Module | Test approach | Notes |
|---|---|---|
| `advisor/profile.ts` | Schema validation (good/bad inputs); atomic write to tempdir; disclaimer enforcement | Uses `os.tmpdir()` + cleanup in `after` hook |
| `advisor/screening.ts` | Pure function with fixture universes; snapshot tests for ranked output | Zero mocks |
| `advisor/market-data/brapi.ts` | Mock `globalThis.fetch` returning golden JSON fixtures; assert URL construction, header use, parse correctness | Fixtures in `tests/fixtures/brapi/*.json` |
| `advisor/market-data/cache.ts` | In-memory SQLite (`:memory:`); TTL boundary tests (just-expired vs just-fresh) | No mocking needed |
